# 플로우 실행 기록 (Flow Runs)

::: warning 실험적 기능
플로우 러너와 실행 기록은 tapflow의 **AI 자동화 축**에 속하는 실험적 기능입니다. 정식 경로는 수동 QA 대시보드입니다.
:::

대시보드의 **Flow Runs** 페이지에서 `tapflow flow run`이 남긴 실행 기록을 볼 수 있습니다. CI가 빌드마다 플로우를 돌렸다면 어느 빌드에서 어느 플로우가 왜 실패했는지 팀원 누구나 브라우저로 확인할 수 있습니다. 실패가 앱 문제인지, 기기·에이전트·릴레이 같은 환경 문제인지도 나눠서 보여 줍니다.

토큰을 주고 실행하면 실행 기록이 남습니다. 설정은 [기록 남기기](#recording)를 참고하세요.

## 사용 방법 {#how-to-use}

1. 대시보드 왼쪽 사이드바에서 **Flow Runs**를 엽니다. 사이드바에는 첫 실행이 기록된 뒤부터 나타나며 처음에는 CI 실행만 보입니다.
2. 위쪽의 **All** / **CI** / **Local**로 어디서 실행된 기록을 볼지 고릅니다. 상태(**Any status**, **Running**, **Passed**, **Failed**, **Cancelled**)와 플로우 이름으로도 좁힐 수 있습니다. 플로우 이름은 일부만 입력해도 됩니다.
3. 행을 누르면 그 실행의 상세 화면이 열립니다. Cmd를 누른 채 클릭하면(Windows·Linux는 Ctrl) 새 탭에서 열립니다.

목록은 한 페이지에 최근 실행부터 25개씩 보여 줍니다. 표 아래의 **Newer**와 **Older**로 페이지를 옮깁니다.

필터는 주소에 들어가므로 걸러 낸 목록을 링크로 공유할 수 있습니다.

### 실행 상세 {#run-detail}

상세 화면에는 플로우가 실행 순서대로 나옵니다.

- 실패한 플로우는 실패 메시지, 스텝별 결과, 실패 순간의 스크린샷을 보여 줍니다. 통과한 플로우는 끝난 화면을 보여 줘서 정말 통과했는지 확인할 수 있습니다. 로그인 플로우라면 로그인 후 화면이 나옵니다. 스크린샷을 누르면 원본 크기로 열립니다.
- `tapOn`이 요소를 찾지 못하거나 여러 요소에 매칭되어 실패한 스텝에는 실패 순간의 화면에서 대신 쓸 만한 줄이 **Try instead** 아래에 나옵니다. 줄마다 **Copy** 버튼으로 복사할 수 있습니다. [플로우 문서](/ko/automation/flows#셀렉터)에서 어떻게 고르는지 설명합니다.
- 끝까지 가지 못한 플로우는 **Not run**으로 표시합니다.
- CI가 실행 링크를 남겼다면 **Open the CI run**으로 CI 쪽 실행 화면을 열 수 있습니다. 빌드가 있는 실행은 **Other runs of this build**로 같은 빌드의 다른 실행 기록을 볼 수 있습니다.

### 플로우 영상 보기 {#flow-video}

러너가 영상을 남긴 플로우에는 **Play the video** 버튼이 있습니다. 버튼을 누르면 플로우를 처음부터 끝까지 녹화한 영상을 내려받아 라이브 화면과 같은 기기 프레임 안에서 재생합니다. 스크린샷이 플로우가 끝난 화면이라면 영상은 거기까지 어떻게 갔는지를 보여 줍니다. 영상은 버튼을 누를 때만 내려받습니다.

- 재생 막대 위의 점은 스텝이 시작한 지점이고 실패한 스텝은 빨간 점으로 표시합니다. 회색 막대는 릴레이에 도착하지 못해 비어 있는 구간입니다. 점이나 막대에 마우스를 올리면 무엇인지 나오고 누르면 그 지점으로 이동합니다.
- 재생 막대를 끌면 스텝이 시작한 지점에 걸립니다. 재생 속도는 0.5배에서 4배까지 고를 수 있습니다.
- 영상이 없는 플로우에는 그 이유가 나옵니다. 에이전트가 JPEG로 보냈거나 기기 스트림에 영상을 시작할 프레임이 없었던 경우, 그리고 보관 기간이 지나 지워진 경우입니다.
- 영상이 일찍 끝났다면 그 이유도 나옵니다. 플로우 하나의 영상이 100 MB에 닿았거나 영상 저장 공간이 가득 찬 경우, 실행이 취소되었거나 러너의 연결이 끊긴 경우, 영상의 끝부분이 릴레이에 도착하지 못한 경우입니다.

### 진행 중인 실행 지켜보기 {#watch-a-run}

실행이 진행 중이면 목록과 상세 화면이 몇 초마다 새로 고침됩니다. 상세 화면의 **Watch the device**를 누르면 러너가 조작하는 기기를 실시간으로 볼 수 있습니다. 보기 전용이라 화면을 눌러도 기기에는 아무것도 전달되지 않습니다. 세션 하나를 동시에 4명까지 볼 수 있습니다.

## 상태의 의미 {#statuses}

| 상태 | 의미 |
|------|------|
| **Running** | 실행 중 |
| **Passed** | 모든 플로우 통과 |
| **Failed** | 하나 이상의 플로우가 앱에서 실패 |
| **Environment problem** | 모든 실패가 앱이 아닌 환경(기기, 에이전트, 릴레이) 문제. 플로우를 시작하기 전에 실패한 실행도 여기에 들어가고 상세 화면에 그 이유가 나옵니다. 앱 회귀가 눈에 띄도록 빨간색이 아닌 회색으로 표시합니다. Status 필터에서는 **Failed**에 포함됩니다. |
| **Cancelled** | 실행이 취소됨(Ctrl+C, CI 잡 취소). 러너가 끝을 알리기 전에 연결이 끊긴 실행도 여기에 들어가고 상세 화면에 그 사실이 나옵니다. |

## 기록 남기기(운영자) {#recording}

- `tapflow flow run`에 API 유형 토큰(`view, builds:write`)을 주면 실행마다 기록이 남습니다. 토큰은 `--token`이나 `TAPFLOW_TOKEN`으로 주거나 [토큰 파일](/ko/automation/mcp-server#token-file)에 둡니다. 자세한 내용은 [플로우 레퍼런스의 실행 기록](/ko/automation/flows#run-records)을 참고하세요.
- 기록하지 않으려면 `--no-record`를 붙입니다.
- 영상 보관은 **Settings → Default**의 **Flow run videos** 카드에서 정합니다(Admin). 통과한 플로우의 영상을 며칠 남길지와 영상에 쓸 저장 공간을 정할 수 있고 지금 얼마나 쓰고 있는지도 보입니다. 기본값은 3일과 20 GB입니다. 실패한 플로우의 영상은 저장 공간이 모자라지 않는 한 실행 기록이 남아 있는 동안 함께 남습니다. 저장 공간이 차면 오래된 통과 영상부터 지우고 통과 영상을 모두 지운 뒤에야 실패 영상을 지웁니다.
- 로컬에서 실행하면 러너가 실행이 끝날 때 그 실행 페이지의 링크를 출력합니다. CI에서는 릴레이 주소가 로그에 남지 않도록 실행 ID만 출력합니다.
- 빌드에 딸린 기록은 그 빌드가 지워질 때 함께 지워지고 빌드 없이 실행한 기록은 7일 뒤 지워집니다.
