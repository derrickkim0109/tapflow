# USB로 연결한 Android 폰

에이전트 맥에 USB로 연결한 Android 폰을 기기 목록에 띄워 에뮬레이터처럼 열 수 있습니다. 화면 스트리밍, 터치, 키 입력, 앱 설치와 실행을 지원합니다. tapflow는 폰을 켜거나 끄거나 지우지 않습니다.

## 폰 목록 켜기 {#turn-on}

이 기능은 기본으로 꺼져 있습니다. 켜면 릴레이에 접속할 수 있는 사람은 누구나 폰의 화면과 알림, 앱과 앱 데이터를 볼 수 있습니다. 외부 접속을 열어 둔 릴레이라면 밖에서도 볼 수 있습니다. 충전하려고 꽂아 둔 개인 폰이 팀 전체에 열리지 않도록, 에이전트를 실행하는 쪽에서 직접 켜야 합니다.

에이전트 프로세스에 환경 변수를 주고 시작합니다.

```sh
TAPFLOW_ANDROID_USB_DEVICES=1 tapflow agent start
```

`tapflow start`로 릴레이와 에이전트를 함께 띄울 때도 같은 변수를 앞에 붙입니다. 값이 `1`이 아니면 꺼진 상태이고, 꺼져 있으면 기기 목록은 이 기능이 생기기 전과 같습니다. 에뮬레이터만 보이고 폰에는 아무 명령도 보내지 않습니다.

개인 폰보다 테스트 전용 폰을 쓰세요. 메신저나 인증 앱처럼 개인 데이터가 있는 앱이 깔린 폰은 연결하지 않는 편이 안전합니다.

## 폰 준비 {#prepare}

1. 폰의 **설정 > 휴대전화 정보 > 소프트웨어 정보**에서 **빌드번호**를 7번 눌러 개발자 옵션을 켭니다. 메뉴 이름은 제조사마다 조금씩 다릅니다.
2. **개발자 옵션**에서 **USB 디버깅**을 켭니다.
3. 폰을 에이전트 맥에 USB 케이블로 연결합니다.
4. 폰에 **USB 디버깅을 허용하시겠습니까?** 창이 뜨면 **이 컴퓨터에서 항상 허용**을 고르고 **허용**을 누릅니다.

에이전트를 시작하기 **전에** 폰을 연결하세요. 에이전트는 시작할 때 기기 목록을 릴레이에 한 번 알리므로, 실행 중에 꽂은 폰은 에이전트를 다시 시작해야 목록에 나타납니다. 뺀 폰도 다시 시작할 때까지 목록에 남아 있다가, 열려고 하면 `Device not found`로 실패합니다.

폰을 쓸 수 없는 상태면 에이전트가 이유를 한 번 출력합니다. 같은 폰이 다른 상태로 바뀌거나 다시 연결되면 또 출력합니다.

| 상태 | 할 일 |
|---|---|
| `unauthorized` | 폰에서 USB 디버깅 허용 창에 답한 뒤 에이전트를 다시 시작합니다. |
| `offline` | 케이블을 뺐다가 다시 꽂고 에이전트를 다시 시작합니다. |
| `recovery` 등 | 폰이 복구 모드처럼 Android가 아닌 상태입니다. Android로 부팅한 뒤 에이전트를 다시 시작합니다. |

무선 디버깅으로 연결한 폰(`ip:port`)은 아직 목록에 나오지 않습니다.

## 폰에서 쓸 수 없는 기능 {#refused}

아래 기능은 에뮬레이터 전용이거나 세션이 끝난 뒤에도 폰을 바꿔 놓기 때문에 거부합니다. 요청하면 그 기능의 오류 메시지로 이유를 알려 줍니다.

- **Full reset**: 폰을 지우게 되므로 거부합니다.
- **네트워크 제어**: 오프라인으로 끝난 세션이 폰을 오프라인으로 남기지 않도록 거부합니다.
- **클립보드**: 아직 지원하지 않습니다.
- **접기와 펼치기**: 폴더블 폰이라도 폰을 직접 접어야 합니다.
- **앱 데이터 지우기**: 이번 세션에 tapflow가 설치한 앱만 지울 수 있습니다. 플로우 실행 전 초기화도 같아서, 그 밖의 앱은 지우지 않고 실패로 보고합니다.

저장 공간이 부족해도 시스템 앱 업데이트를 되돌려 공간을 만들지 않습니다. 영상은 늘 scrcpy로 받으므로 `TAPFLOW_ANDROID_BACKEND=grpc`를 줘도 폰에는 적용되지 않습니다.

`tapflow flow run`과 MCP 서버처럼 플랫폼만 지정해 기기를 빌리는 요청은 폰을 고르지 않습니다. 폰에서 실행하려면 그 기기를 직접 지정합니다.

### 앱 설치 {#install}

에뮬레이터는 설치할 때마다 앱 데이터를 비우고 시작하지만, 폰은 이미 있는 앱 위에 덮어 설치하므로 **앱 데이터가 남습니다**. 빈 상태에서 시작하려면 설치한 뒤 앱 데이터 지우기를 쓰세요. 빌드와 같은 패키지 이름의 앱이 서명이 달라 설치가 실패해도 그 앱의 데이터는 그대로입니다.

### 설치가 멈출 때 {#install-prompt}

폰에서 **USB를 통해 설치된 앱 확인**이나 Play 프로텍트 검사 창이 뜨면 `adb install`이 답을 기다리며 멈춥니다. tapflow는 120초에 APK 1MB당 1초를 더한 시간이 지나면 설치를 실패로 알립니다. 폰에 창이 떠 있으면 답한 뒤 다시 설치하세요. 개발자 옵션의 **USB를 통해 설치된 앱 확인**을 끄면 창이 뜨지 않습니다. 창이 없는데 실패했다면 느린 연결에서 큰 빌드를 설치하느라 시간이 모자란 것이니 `TAPFLOW_ANDROID_USB_INSTALL_TIMEOUT_MS`로 늘리세요.

## 회전 설정 {#rotation}

**Rotate**를 누르면 tapflow가 폰의 회전을 잠급니다. 폰의 자동 회전도 함께 꺼집니다. 세션이 끝나면 세션 전의 회전 설정으로 되돌립니다. 자동 회전이었으면 자동 회전으로, 잠겨 있었으면 원래 방향으로 돌아갑니다.

- 세션 중에 에이전트를 멈추면(Ctrl+C) 종료하면서 되돌립니다.
- 되돌리지 못한 경우(폰을 먼저 뺐거나 에이전트가 비정상 종료한 경우)에는 원래 설정을 `~/.android/tapflow-usb-rotation.json`에 남겨 두고, 다음에 에이전트가 그 폰을 목록에서 볼 때 되돌립니다. `ANDROID_USER_HOME`을 설정했다면 그 디렉터리에 저장합니다.

`wm user-rotation` 명령이 없는 구형 Android 폰에서는 회전이 동작하지 않습니다.

## 폰에 남는 것 {#left-on-phone}

tapflow는 화면 스트리밍용 scrcpy 서버와 UI 트리를 읽는 파일을 폰의 `/data/local/tmp`에 올리고, 세션을 정상적으로 종료하면 지웁니다. 세션 중에 폰을 빼거나 에이전트를 멈추면 파일이 남을 수 있고, 그 폰으로 연 다음 세션을 정상적으로 종료할 때 지웁니다. 개발자가 따로 쓰는 scrcpy와는 파일 이름이 달라 서로 덮어쓰지 않습니다.

스트리밍하는 동안에는 폰 화면이 꺼지지 않습니다. 잠금 화면이 뜨면 뷰어에서 PIN을 입력해야 하고, 그 입력은 릴레이를 거칩니다. 화면 캡처를 막는 앱은 검은 화면으로 보입니다.
