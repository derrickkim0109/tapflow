A USB-connected Android phone can be offered beside the emulators (#152), **only with `TAPFLOW_ANDROID_USB_DEVICES=1` on the agent**; off by default, the listing is what it was before: emulators only, and no shell on any other device. With it on, every row of `adb devices` in state `device` that is not an emulator or a network serial is listed as `usb:<serial>`, reported as a physical device, named from `ro.product.marketname`, the phone's device name, or `ro.product.model`, its properties read with a 10 s bound so a phone that does not answer is left out rather than holding up the listing. A phone adb cannot drive — unauthorized, offline, in recovery — is named in the agent's output once per state it reaches, with no restart asked of it. Emulators are reported as emulators. Phones are part of the 30 s device list re-read exactly as of the register, so a phone plugged in or unplugged while the agent runs is offered or withdrawn without a restart. One that leaves the list has its session state retired as a reconnect retires it — its scrcpy session stopped by the serial in its id even once the serial map has dropped it, tapflow's claim on it and its install record forgotten — and a rotation lock it still owes is kept; plugged back in, it is described afresh and the lock is written back by that listing, the re-read included. A phone's boot starts scrcpy and input only — no launch, wipe, gRPC, Lean mode or network reset — and always on scrcpy: `TAPFLOW_ANDROID_BACKEND=grpc` now applies to emulators only, where it used to send a non-emulator serial to the first emulator's gRPC port. Its shutdown stops only the stream and, on a normal shutdown, removes the scrcpy server and tree dump tapflow pushed to `/data/local/tmp`. Full reset, network control, the clipboard and postures are refused on a phone through each message's error reply. On a phone, `app:install` no longer runs `pm clear` on the build's package first — the package comes from the build record, so it could name an app of the phone's owner — and `install -r` keeps the app's data; `app:clear-state` and a run reset's app-data step clear only a package tapflow installed in the session, and report any other as failed. Storage is never reclaimed on a phone, and an install there fails after 120 s plus 1 s per MB of the APK (`TAPFLOW_ANDROID_USB_INSTALL_TIMEOUT_MS` overrides it, `0` for none), with a message naming both a prompt on the phone and a slow install. The rotation lock a phone had at boot is written back at shutdown, synchronously on the agent's exit, or by the next listing that sees it, in this agent or the next (#1033): the agent goes by its own map and keeps a copy in `tapflow-usb-rotation.json` beside adb's keys, replaced whole through a temporary file. The scrcpy server is pushed as `tapflow-scrcpy-server.jar`, and a stream restart kills only its own server by `scid` (by that jar's path when no session names one), so a scrcpy a developer runs on the same phone is left alone. This applies to every device on the scrcpy path, emulators included: an emulator streaming without gRPC gets the renamed jar too, and its restart no longer kills every `scrcpy-server` on it.

The relay never hands a USB phone (`kind: 'physical'`) to a `device:lease`, which names only a platform: a run uses a phone only by naming its session. A lease refused because only phones are left says so.
